## 与 ModelDeps 证据链连接

使用 README 中的 `plan` → `verify` → `apply` 流程；把真正执行上述断言的命令交给 `verify --command`。保存计划、eval JSON/Markdown、原始测试报告、退出码、项目提交和配置版本。命令必须在断言失败时返回非零退出码。

业务代码、Registry、配置或评测输入改变后，重新生成对应计划和证据。`apply` 默认 dry-run，高风险迁移仍需人工处理；评测通过只能说明所配置的测试通过。只有业务负责人完成此表后，才能把“真实业务验收”改为已完成。
